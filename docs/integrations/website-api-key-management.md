# Ключи CheckoutV2 в CRM

Локальная реализация. На рабочем сервере этот интерфейс пока не установлен.

## Создание

1. Войдите как владелец и откройте **Настройки → Учётная запись → Ключи API сайта**.
2. Укажите понятное имя ключа. Источник — `calendar.yoleotard.com`.
3. Введите текущий пароль владельца и подтвердите операцию.
4. Скопируйте новый секрет в безопасное хранилище или настройки интеграции WordPress. CRM покажет его только один раз. После закрытия окна восстановить секрет нельзя.

В списке остаются имя, публичный идентификатор, источник, даты создания/использования/отзыва и автор операции. Публичный идентификатор не заменяет полный ключ. Значение существующего серверного токена не показывается; доступен только признак его настройки.

## Ротация

Создайте новый ключ действием ротации. При необходимости измените **Аккаунт сайта** на canonical hostname, который WordPress будет отправлять в `sourceAccount`. Новый ключ принимает заказы только для выбранного аккаунта; старый ключ и его аккаунт остаются без изменений. Установите новый ключ в WordPress и выполните согласованную проверку доставки заказа без дублирования. Только затем отдельно отзовите старый ключ с подтверждением и текущим паролем. CRM не отзывает старый ключ автоматически.

Если окно с новым секретом закрыто до копирования или ответ потерян, отзовите этот ключ и создайте другой. Повторного показа нет. При потерянном ответе сначала обновите список, чтобы увидеть, завершилось ли создание.

Отзыв прекращает последующую авторизацию ключом. Уже авторизованный запрос может завершиться. Дата последнего использования обновляется с интервалом не чаще пяти минут; она не является журналом каждого запроса или доказательством создания заказа.

## Защита

Ключ разрешает только website orders API для указанного источника. Он не предоставляет доступ к страницам или другим API CRM. В базе хранится только версия алгоритма и хеш случайного 256-битного секрета вместе с публичными метаданными. Отозванные записи и аудит сохраняются.

Для новых ключей действует лимит 120 попыток авторизации с одного IP за 60 секунд. При недоступности защиты Redis новые ключи временно отклоняются; корректный прежний env-токен продолжает проверяться независимо. Управление ключами имеет отдельные лимиты по владельцу и IP.

Не вставляйте ключи в комментарии, URL, скриншоты, задачи или переписку. CRM не сохраняет секрет в браузерном хранилище и не отправляет его в аудит. Копирование выполняется только по нажатию пользователя; буфер обмена контролируется операционной системой.

Существующий `WEBSITE_ORDERS_API_TOKEN` остаётся независимым серверным резервным способом авторизации с прежним списком источников. Управление новыми ключами его не изменяет.

## Развёртывание и восстановление

Только после отдельного разрешения владельца: резервная копия с проверкой восстановления, применение новой аддитивной миграции, совместное обновление API и интерфейса, проверки OWNER-доступа и отказов до любых реальных заказов. Рабочие ключи создаёт владелец через интерфейс. Ключи и аудит не удаляются при откате приложения. После перехода WordPress исключительно на ключи из базы нельзя откатывать API на код, понимающий только env-токен, без согласованного совместимого пути восстановления.
