# Скачивание резервных архивов на Windows

Статус: подготовлен локальный установщик; **на этом этапе ничего не установлено
и не активировано**. Задачи Windows не регистрировались, реальные токены не
читались. Публикация файлов и активация требуют отдельного действия оператора.
Это PULL-клиент существующих архивов CRM, а не второй механизм создания backup.
Скачанная копия не является доказательством восстановления.

## Что потребуется

- Windows с Python 3.9+ и `pythonw.exe` (обычная установка Python для текущего
  пользователя); PowerShell 5.1+. Сторонние Python-пакеты не нужны.
- Доступ к `https://crm.yoleotard.com` с действительным TLS-сертификатом.
  HTTP, отключение проверки сертификата и перенаправления запрещены.
- Локальный диск и свободное место под архив плюс резерв 256 МиБ.
  По умолчанию папка `D:\YO_CRM_Backups`. Если диска D нет, оператор задаёт
  существующий локальный диск в настройках CRM. Сетевые UNC-пути, относительные
  пути, junction/symlink назначения не поддерживаются.
- Токен сопряжения, отдельно выданный в CRM пользователем OWNER/ADMIN.
  Backend ограничивает срок 90 днями и связывает доступ с активностью и ролью
  выдавшего пользователя; отзыв, истечение срока или потеря роли прекращают
  доступ. Helper не получает пароль CRM и не продлевает токен автоматически.

## Явная установка оператором — не выполнять при разработке

1. После отдельного разрешения на публикацию скачать доверенный
   `/backup-sync/Install-YoCrmBackupSync.ps1` с адреса своей CRM. Проверить источник
   самого установщика: встроенный hash защищает загружаемый helper, но не
   заменяет доверие к установщику. Обе версии должны публиковаться вместе.
2. Открыть обычный PowerShell **от своего пользователя**, без запуска от
   администратора. Перейти в папку со скачанным файлом и запустить:

   ```powershell
   .\Install-YoCrmBackupSync.ps1
   ```

   Если политика Windows запрещает скрипт, использовать одобренный организацией
   способ разрешения конкретного файла; установщик сам политику не меняет.
3. Подтвердить адрес CRM (Enter — `https://crm.yoleotard.com`), резервную папку
   (Enter — `D:\YO_CRM_Backups`) и ввести токен в скрытом приглашении
   `Read-Host -AsSecureString`. Не передавать токен параметром команды, через
   переменные окружения, файл или переписку. Не включать внешнюю отладочную
   трассировку процессов/ввода при сопряжении.
4. Установщик скачает helper с **того же origin**, сверит встроенный SHA256 и
   сохранит его в `%LOCALAPPDATA%\YOCRMBackup`. Каталог и наследуемые ACL файлов
   ограничены текущим Windows-пользователем. Origin, резервная папка и Bearer
   сохраняются вместе в `config.dpapi`, зашифрованном Windows DPAPI CurrentUser
   через Python ctypes/stdlib. Открытый токен существует лишь в памяти и
   анонимном stdin pipe; его нет в файлах, логах, аргументах или окружении.
5. Только после успешного сохранения создаётся пользовательская задача
   `YOCRMBackupSync`: при входе пользователя и каждые **5 минут**, скрытый
   `pythonw.exe`, Interactive/Limited, без пароля компьютера и без админ-прав.
   Первая периодическая проверка назначена примерно через минуту. Установщик
   сам не выполняет download или серверный backup. Проверить имя задачи,
   триггеры и «Результат последнего запуска» в Планировщике заданий Windows.
   Локальные политики организации могут запрещать регистрацию задачи.

Папка, указанная **сервером**, имеет приоритет. Локальная папка из установщика —
только fallback, если сервер не прислал папку. Изменение папки на сервере
разрешает запись последующих архивов в новую локальную папку; старые файлы
остаются. После завершения текущего обхода списка helper снова начинает с
начала: уже скачанные файлы проверяются, а в новой папке отсутствующие архивы
скачиваются. Перемещение старых локальных файлов оператор выполняет отдельно.

## Режим и интервал

При каждом запуске helper сначала выполняет только
`GET /api/backup-sync/archives?cursor=...` с `Authorization: Bearer ...`.
Ожидаемый ответ:

```json
{
  "mode": "AUTOMATIC",
  "folder": "D:\\YO_CRM_Backups",
  "intervalMinutes": 30,
  "archives": [{
    "id": "safe-archive-id",
    "type": "FULL",
    "createdAt": "2026-10-26T00:00:00Z",
    "archiveChecksum": "<64 hexadecimal SHA256 characters>",
    "archiveBytes": 12345
  }],
  "nextCursor": "opaque-checkpoint"
}
```

`MANUAL` — тихий выход **до создания папки назначения**, без скачивания и без
изменения cursor. Поддерживаются также строчные `manual/automatic`.
`AUTOMATIC` — скачивание с интервалом `intervalMinutes` 5–1440 минут; отсутствующее
или некорректное значение означает 30 минут. После чтения ответа helper
сравнивает текущее время и `lastSuccessfulRun` по **текущему** серверному
интервалу. Поэтому изменение интервала применяется без переустановки даже до
старого `nextDue`. Состояние фиксирует `lastSuccessfulRun`, `nextDue` и cursor
только после успешной проверки всей полученной страницы; сбой повторяется при
следующем опросе. Пустая успешная страница тоже считается успешным опросом.
`nextCursor: null` завершает обход и сбрасывает checkpoint. На следующем
интервале начинается новый обход с начала списка: это позволяет найти старый
по дате создания архив, который завершился уже после прохождения его позиции.
За один запуск обрабатывается только одна страница (до 100 записей API);
полный обход большого списка занимает несколько интервалов. Уже скачанные
файлы повторно сверяются по размеру/SHA256 и не загружаются заново при совпадении.
`archiveBytes` принимается как целое число либо десятичная строка BigInt API,
без преобразования через float.

Для каждого архива выполняется
`GET /api/backup-sync/archives/:id/download`. Только безопасный id становится
именем `YO_CRM_<id>.tar.gz`: имя из HTTP-заголовков не используется. Файл
принимает id по core-контракту `[A-Za-z0-9][A-Za-z0-9._-]{7,127}`, включая точки
старых архивов; разделители пути и traversal не допускаются. Архив
пишется потоково в эксклюзивный `YO_CRM_<id>.tar.gz.<UUID>.partial` каждой новой
попытки, сбрасывается через fsync,
проверяется по SHA256 и точному числу байтов, затем атомарно переименовывается
на Windows без перезаписи существующего файла. Идентичный файл проверяется и
пропускается; конфликт сохраняет исходный файл и блокирует продвижение cursor.
Предсуществующие `.partial` не удаляются и не мешают следующей попытке скачать
тот же архив: она использует новый UUID. После обрыва питания старый partial
может остаться; его удаление — отдельное решение оператора. Обычная ошибка
удаляет лишь созданный временный файл текущей попытки. Существующий итоговый
файл проверяется полностью по SHA256 и размеру; тот же id с иными байтами,
включая одинаковую длину, остаётся конфликтом без перезаписи.

Атомарная запись настройки и cursor также использует отдельный
`<имя>.<UUID>.tmp` для каждой попытки. Чужие и оставшиеся после аварии `.tmp`
не удаляются автоматически и не блокируют следующие записи. При обычном сбое
удаляется только temp, успешно созданный текущей попыткой; предыдущее
зафиксированное состояние сохраняется до успешного атомарного replace.

До записи байтов новый `.partial` получает защищённый ACL только текущего
Windows-пользователя и SYSTEM; после переименования этот ACL сохраняется.
Права существующей папки, старых архивов и посторонних файлов не меняются;
рекурсивного изменения ACL назначения нет. Путь проверяется до mkdir:
drive-backslash, не более 240 символов, без UNC/root/dot-segments, завершающих
точек/пробелов, forward slash, двойных кавычек, апострофа, backtick и управляющих символов.
На Linux тесты подставляют только преобразование временной папки и ACL seam;
производственная проверка остаётся строго Windows.

**Обычные архивы не зашифрованы на диске. DPAPI защищает только настройку с
токеном, а ACL ограничивает доступ к файлам.** Архивы содержат персональные
данные; защиту локального диска и физического доступа обеспечивает оператор.

Удаления или retention архивов на ПК нет. Helper не создаёт архивы, не вызывает
restore, не активирует провайдеры, не меняет production. Он проверяет целостность
байтов архива; внутреннюю структуру и возможность восстановления проверяют
отдельные инструменты резервного копирования.

## Когда задача работает

Браузер может быть закрыт. Пользователь должен оставаться вошедшим в Windows;
блокировка экрана работе не мешает. После выхода из профиля работа не идёт.
При сне, гибернации или выключенном компьютере проверок нет, пока компьютер
снова не доступен с вошедшим пользователем. Задача не будит компьютер; после
возобновления сработает доступный триггер/очередная проверка.

При сетевой ошибке, 401/403, истёкшем токене, конфликте файла, несовпадении hash
или нехватке места cursor не меняется. В Планировщике будет результат 1;
подробные ответы сервера, URL с секретами и текст исключений не логируются.
Перепроверить сеть, pairing и место. После отзыва/истечения выдать новый токен и
повторить установку. Копирование `config.dpapi` в другой профиль/на другой ПК не
является переносом настройки: требуется новое сопряжение.

## Отключение и удаление — только оператором

```powershell
.\Install-YoCrmBackupSync.ps1 -Disable
.\Install-YoCrmBackupSync.ps1 -Remove
```

`-Disable` останавливает/отключает задачу, оставляя настройку и все архивы.
Для включения повторить установку. `-Remove` также удаляет задачу и только
известные файлы helper/настройки в `%LOCALAPPDATA%\YOCRMBackup`; архивы на диске
не трогаются. На сервере отдельно отозвать токен компьютера, если доступ больше
не нужен. Принудительная остановка во время скачивания может оставить `.partial`.

## Локальная проверка разработки

```powershell
python -B scripts/tests/backup_desktop_test.py
```

Тесты используют fake HTTP opener, реальные временные файлы и поддельный
DPAPI seam; проверяют manual, server folder/interval, traversal, TLS/redirect,
checksum/bytes, partial, reserve, cursor и отсутствие утечки секрета, а также
точное совпадение embedded SHA256 установщика с байтами helper. Ни один тест не
регистрирует и не запускает ScheduledTask. На Windows отдельно выполняется
настоящий DPAPI roundtrip **исключительно синтетических байтов** в TempDirectory,
без CRM-токена и без установки; на других платформах только этот тест skipped.
Реальная цепочка urllib с поддельным транспортом проверяет 301/302/303/307/308
для list и download: запросы и Authorization на чужой origin не отправляются.
Нативный тест ACL ограничен TempDirectory: новый архив имеет только CurrentUser
и SYSTEM, ACL родительской папки и постороннего файла остаются прежними.
Реальное сопряжение, ACL установленного профиля и работа при входе/блокировке/
возврате из сна остаются непроверенными до отдельного разрешённого операторского теста.
Независимые review-агенты в текущей сессии недоступны; локальная проверка не
подменяет обязательный независимый release gate проекта.

Локальная проверка 2026-10-26: Windows, Python 3.10; 48 тестов helper, включая
нативные синтетический DPAPI и ACL временных файлов. Синтаксис PS1 проверен
через PowerShell 5.1 AST `Parser.ParseFile`, без исполнения. `pnpm typecheck`
и `pnpm build` прошли. Запущенный общий `pnpm quality:check` остановился на
параллельно изменявшихся backend-тестах `computer-transfer.test.mjs`
(пустой список вместо архива и timeout download); helper не меняет эти файлы.
Общий gate требует повторной проверки интегратором после стабилизации backend.

Ограниченный handoff этой задачи находится здесь: изменяются только
установщик, helper, его тест и данный документ; `CHAT_HANDOFF.md` не изменялся
из-за явно заданной границы четырёх файлов. Нет commit, deploy, установки,
активации задачи или чтения настоящих credentials.
