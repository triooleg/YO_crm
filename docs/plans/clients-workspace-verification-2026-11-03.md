# Проверка обновлённого раздела «Клиенты»

Дата: 03.11.2026. Checkout: `codex/clients-workspace-refresh`, база `c91c747`.
Это локальная разработка по YO_CRM_Clients_Codex_Package.zip. Рабочий сервер,
его база и установленная версия не менялись. Commit/push не выполнялись.

## Реализовано

- Таблица клиентов, серверный поиск/фильтры/сортировка, страницы 15/20/50,
  URL выбранного клиента, контакты с копированием, каналы и счётчики заказов.
- Подробная карточка справа; на узком экране — Mantine Drawer. Пять вкладок:
  обзор, заказы, переписка, заметки, файлы. Переписка и файлы загружаются лениво.
- Существующие заказы и миниатюры дизайнов, несколько дизайнов/экземпляров,
  отсутствие фото, реальные валюты. Фактические оплаты отделены от стоимости.
  Неизвестный курс не превращается в ноль. Номер сайта сохраняет provenance.
- Существующие спортсменки и неизменяемые snapshots измерений. Устаревшие
  измерения не подставляются в новый заказ без отдельного согласия.
- Создание клиента с проверкой дубликатов; одно имя не означает одного клиента.
  Поиск дубликатов показывает доказательства совпадений и слабые совпадения имён.
- Ручное пакетное объединение поверх существующей транзакции merge/split:
  выбранная основная карточка, сравнение полей, точные значения подтверждения,
  контроль устаревшего preview, блокировка конфликтов каналов/идентичностей.
- Существующие заметки, видимость и аудит. Метка «клиентская» не отправляет
  сообщение и не публикует данные. Файлы выбираются только по владельцу.
- Переход из «Входящих» к client ID и обратно к точному conversation ID с
  сохранением фильтров и штатной защитой несохранённого черновика.

## Совместимость и данные

Новых таблиц истории/контактов нет. Старый GET /clients без view возвращает
прежний массив; новое представление — opt-in. Старый одиночный merge сохраняет
контракт. Идентификаторы, файлы, заказы, спортсменки, сообщения и измерения не
пересоздаются. Архивные заказы исключены из показателей, отменённые считаются
отдельно по действующим правилам. Денежные данные не изменяются.

Нужна одна добавочная миграция защиты ClientFile при merge/split. Она не
выполнена на production. До наличия проверенных триггеров merge/split возвращает
локализованную ошибку; API проверяет каталог и полные fingerprints функций.
Новые сообщения/платежи/измерения сохраняют прежние FK родителей, их количество
не блокирует подтверждение объединения. Существующие ограничения split остаются:
произвольный откат после несвязанных изменений не обещается.

## Производительность

Изолированная PGlite/PostgreSQL-фикстура: 10 000 клиентов, 50 000 заказов.
Страница 20 и 50 клиентов выполняет по 5 обращений к БД: агрегат страницы,
плоская выборка выбранных ID и три словаря фильтров. N+1 вложенных relation
загрузок нет. Последний локальный замер: 266/214 мс соответственно; это не SLA
рабочего сервера. Планы и повторные измерения: `.local/clients-performance.json`.
Поиск 2000 совпадающих имён ограничивает выдачу до пагинации и не строит полное
квадратичное множество пар; связанные кандидаты ограничены с явной пометкой.
