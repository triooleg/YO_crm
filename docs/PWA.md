# Установка YOleotard CRM

CRM использует Next.js App Router и Mantine. Рабочие разделы открываются внутри существующей оболочки по параметру `section`. Установка запускает обзор, затем оболочка проверяет текущую сессию через `/api/auth/me`. Та же проверка применяется к ссылкам из обычной браузерной вкладки. Серверная авторизация, роли, REST API и схема PostgreSQL остаются прежними.

## Установка и обновление

- Android Chrome и настольные Chromium-браузеры показывают предложение внутри CRM, когда браузер предоставляет нативное событие установки. Safari на iPhone и iPad показывает инструкцию для меню «Поделиться».
- После отказа инструкция и нативная установка, если доступна, остаются в настройках CRM. В standalone-режиме предложение скрывается. Safari может изолировать данные установленного приложения от вкладки браузера. В этом случае вкладка не узнает об установке автоматически.
- Service worker регистрируется по HTTPS и проверяет маркер версии и ревизии сборки. Контролируемые окна продолжают работу до закрытия. CRM предлагает сначала сохранить изменения. Принудительного обновления страницы и записи черновиков в локальное хранилище нет.
- Cache Storage содержит только публичные неизменяемые JS, CSS и шрифты из сборки Next.js. HTML, авторизация, REST API, фото, эскизы и файлы требуют обычного серверного доступа. Работа с данными CRM требует сети.

## Сценарии для проверки на устройствах

1. Установить CRM из Android Chrome, Safari на iPhone/iPad и настольного браузера. Проверить иконку, запуск в отдельном окне и вход с действующей и истёкшей сессией.
2. В вертикальном и горизонтальном положении открыть обзор, клиентов, заказы, производство, замеры, финансы и доставку. Проверить доступность списка и действий в карточках, скролл таблиц и размещение кнопок рядом с системными зонами экрана.
3. В карточке заказа выбрать фото из галереи и сделать новый снимок через системный выбор, если устройство предлагает камеру. Проверить JPG, PNG и WebP, предпросмотр эскиза и загрузку разрешённого вложения. В форме замеров проверить просмотр фото и ввод с экранной клавиатуры.
4. Открыть CRM в двух окнах и оставить незаполненное поле в одном из них. Опубликовать сборку с новым `CRM_COMMIT`, вернуть окно на передний план, проверить сообщение об обновлении и сохранность ввода. Сохранить работу и закрыть оба окна, затем запустить новую сборку.

## Web Push 0.21.0

В настройках CRM раздел «Уведомления на устройстве» позволяет отдельно выбрать «Новые сообщения» и «Заказы с сайта». Оба события изначально выключены. Выбор сохраняется по кнопке «Сохранить уведомления», разрешение браузера запрашивается только при этом нажатии. Сохранённые темы восстанавливаются для текущего пользователя, сессии и подписки устройства. Доступ к подписке проверяется сервером. При отказе браузера CRM предлагает изменить разрешение в настройках браузера.

Серверная отправка требует `WEB_PUSH_ENABLED` и настройки VAPID. Приватный ключ VAPID остаётся на сервере, frontend получает публичный ключ. `GET /web-push/config` получает доступность и публичный ключ. `POST /web-push/subscriptions/current` получает темы текущей подписки с endpoint в JSON body. `PUT /web-push/subscriptions` сохраняет endpoint, ключи подписки и темы, `DELETE /web-push/subscriptions` отзывает подписку. Endpoint передаётся только в JSON body. Ответ конфигурации и клиентский запрос используют `no-store`.

Backend связывает подписку с живой сессией и разрешает отправку пользователям OWNER, ADMIN и MANAGER. Источники событий ограничены сохранёнными входящими сообщениями и оплаченными покупками сайта. Sandbox-покупки исключены. Серверная реализация использует durable outbox. Настройка frontend и worker проверена локально с подменёнными границами HTTP и browser Push API. Реальная доставка через push-провайдер на физических устройствах остаётся непроверенной.

Worker показывает фиксированный заголовок «YOleotard CRM» и нейтральный текст о сообщении или заказе. Текст, URL и приватные поля из payload игнорируются. Payload не записывается в Cache Storage. Для сворачивания повторных уведомлений worker принимает только tag вида `crm-push-` с 1–100 символами `a-z`, `A-Z`, `0-9`, `_` или `-` и устанавливает `renotify: false`. В notification data сохраняется только каноническая ссылка `/?section=inbox` или `/?section=orders`. При нажатии worker проверяет точное соответствие разрешённой относительной ссылке и origin, фокусирует существующее корневое окно CRM того же origin, отдавая приоритет нужному разделу даже с дополнительными query-параметрами. Окно сохраняет текущий URL и несохранённый ввод. Новое окно открывается только при отсутствии подходящих окон CRM. CRM проверяет сессию и доступ при обычной загрузке.

Кнопка «Отключить на этом устройстве» сначала отзывает серверную подписку, затем вызывает browser unsubscribe. При выходе CRM выполняет best-effort очистку устройства с общим лимитом две секунды, затем продолжает logout. Проверка живой сессии на backend прекращает последующие отправки после выхода независимо от результата очистки браузера.

### iPhone и iPad

Откройте CRM в Safari, нажмите «Поделиться», затем «На экран „Домой“» и «Добавить». Если предложен переключатель «Открывать как веб-приложение», включите его. Запустите CRM с главного экрана, войдите, откройте «Настройки» → «Уведомления на устройстве», выберите события и сохраните настройки. Во вкладке Safari показывается инструкция установки. В неподдерживаемом браузере показывается сообщение о недоступности push. Установка, запрос разрешения и фактическая доставка на физическом iPhone/iPad требуют отдельной проверки.
