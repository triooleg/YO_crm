# Аудит резервирования YO CRM — 26.10.2026

Статус: аудит выполнен, локальная реализация и её приёмка продолжаются.
Рабочая база и действующие сервисы не изменялись. Результаты аудита и план
представлены владельцу до реализации. Исходное ТЗ и локальный план:
`docs/plans/backup-disaster-recovery.md`.

## Что было в опубликованной 0.10.0

Существуют BackupsModule, Backup/BackupSetting, LOCAL storage, заявки и audit,
CLI dump/uploads, v2 manifest/checksums и ограниченный restore v1/v2. Создание
через API только регистрировало PENDING; исполнитель/lease не подключены.
Расписание было чистой функцией без действующего worker. FULL имел такой же
состав, как DATA: переносимого приложения и offline-образов в нём не было.
Последовательные pg_dump и tar сами по себе не гарантировали согласованность
между базой и файлами. UI резервирования отсутствовал. Retention не удалял
файлы; production restore через API запрещён — этот запрет сохраняется.

## Проверенная инфраструктура и границы

- CRM: PostgreSQL16, отдельный uploads volume, приватный bind-каталог backups;
  Redis классифицирован как восстанавливаемый cache, исходные данные в БД.
- В PostgreSQL находятся заказы, архивные записи, клиенты, спортсменки, снимки
  измерений, оплаты, налоги, переписки, история/audit, задачи, шаблоны и настройки.
  Сохранённые PDF/HTML инвойсов находятся также в AppSetting, не только uploads.
- В uploads расположены order-models/order-files/client-files/task-images,
  communication-files/private-parent-measurements и branding.
- Chatwoot4.17.0 обслуживают отдельные web и sidekiq, общий volume `/app/storage`.
  Его отдельная БД — PostgreSQL15.4 с pgvector. Копия CRM не включает эти тома.
- Секреты Chatwoot, CRM `.env`, SETTINGS_ENCRYPTION_KEY, proxy/SSL не выгружались.
  Шифротекст интеграционных настроек в dump не заменяет исходный ключ.
- Часть импортированных сообщений содержит внешние media URL. URL не доказывает,
  что содержимое вложения сохранено локально. Gmail/Meta/KeyCRM тоже остаются
  внешними зависимостями в соответствующей части.

Текущие агрегаты Chatwoot, прочитанные без изменения данных: 70 переписок,
1517 сообщений, 120 записей вложений, 171 ActiveStorage blob, 168 файлов storage.
Эти числа не обязаны совпадать с CRM: в ней есть и другие каналы.
В CRM на момент аудита:305 переписок,3551 сообщение,139 локальных communication
attachments. Нельзя объявлять полное покрытие Chatwoot по этим локальным данным.

На сервере имеется около16GiB свободного места. Системные Docker/Node/Python
доступны, restic/age не установлены. На рабочем компьютере Docker не найден.
Владелец выбрал временное внешнее хранение скачанных копий на своём компьютере;
S3/второй сервер пока не настроены. Скачивание не равно проверенной offsite-копии.

## Фактический изолированный restore существующей копии

Источник: ранее созданный архив `20261026T133236Z-pre-invoice-number-logo-67ffdd8e`.
Он использован только для чтения; новая production-копия не создавалась.
Восстановление выполнено в новом Docker-проекте, отдельной БД и отдельном
каталоге uploads. Контейнеры не имеют публичных портов, сеть `internal:true`,
нет production mounts; подключения используют синтетические учётные данные БД,
отдельные секреты рабочего окружения не передавались. Сам dump остаётся
чувствительным и содержит сохранённые хеши/шифротекст. Nest/provider workers не
запускались. Базы и файлы остаются на сервере в приватной тестовой среде.

Первый запуск тестовой среды выявил обращение Corepack к npm registry при

read-only inventory хранится в прежнем приватном transport-каталоге. В репозиторий
не включаются реальные архивы, ключи, пароли, содержимое сообщений и файлы клиентов.

## Следующие проверки новой реализации

Новые DATA/FULL, непротиворечивость manifest/API/worker, реальная очередь,
crash/lease/idempotency, расписание/DST, quarantine и отрицательные архивы,
шифрование/расшифровка на синтетических данных, отдельный restore/install,
скачивание по HTTP и интерфейс desktop/mobile. Итоговая приёмка должна отличать
выполненные проверки от неподключённых production/offsite/Chatwoot компонентов.
