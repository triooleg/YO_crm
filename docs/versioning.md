# Версии YO CRM

Проект использует [Semantic Versioning 2.0.0](https://semver.org/lang/ru/).
Формат версии приложения — `MAJOR.MINOR.PATCH`, без ведущих нулей.
`0.1.66` — допустимый номер: компоненты не ограничены одной цифрой.

## Правило следующих выпусков

- Совместимые исправления: PATCH (`0.2.0` → `0.2.1`).
- Новые совместимые возможности: MINOR с обнулением PATCH (`0.2.1` → `0.3.0`).
- Пока MAJOR=0, API развивается: несовместимое изменение требует отдельного
  MINOR, документированной миграции и предусмотренного проектом согласования.
- `1.0.0` будет объявлением стабильного публичного контракта. После него
  несовместимое изменение повышает MAJOR (`1.4.2` → `2.0.0`).
- В одном выпуске выбирается наибольший уровень изменения. Несколько исправлений
  в одном выпуске не требуют нескольких последовательных PATCH.

Это соглашение проекта для разработки `0.x`; SemVer допускает изменения API до
`1.0.0` и не делает прежние номера `0.1.x` синтаксически неправильными.
Текущий пакет новых источников, фильтров и согласования статусов выпускается как
`0.2.0`. Черновой `0.1.68` не публиковался. Опубликованные `0.1.0`–`0.1.67`, их
Git-теги, история изменений и точки отката сохраняются без перенумерации.

## Граница совместимости и идентичность

Версия относится к развёрнутому CRM-приложению. Его внешние контракты —
документированные REST DTO/ответы и RBAC, provider/webhook payloads, URL переходов,
экспорт и сохранность бизнес-истории; документы модулей и контрактные тесты
уточняют детали. Числовые коды enum остаются стабильными идентификаторами.
Внутренние версии workspace-пакетов не являются отдельными релизами CRM.

`package.json` — источник версии интерфейса; Docker defaults, журнал UI,
`CHANGELOG.md` и тег `crm-vX.Y.Z` должны совпадать. Git SHA указывает точный код,
а не заменяет версию. Каждый опубликованный тег неизменяем. Проверки версии,
сборки, тесты, обязательные reviewers и backup-first deployment сохраняются.
