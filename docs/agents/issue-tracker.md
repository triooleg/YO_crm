# Issue tracker: GitHub

Issues and specifications for this repository live in GitHub Issues at the
repository inferred from `origin` (`triooleg/YO_crm`). Use `gh` from this clone
to read or write them.

Creating, editing, labelling or closing an issue is an external write. Perform
it only when the user's current request authorizes publishing to the tracker.
Draft issue text in the repository or a temporary file first when review is
needed. Pull requests are not a triage request surface.

When a skill says to publish a spec or ticket, create a GitHub issue with a
clear title, acceptance evidence and dependency links. Use native sub-issues and
dependencies for `$wayfinder` when available; otherwise record `Part of #...`
and `Blocked by: #...` explicitly.
