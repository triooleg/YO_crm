# Валюты доставки и расходов — локальная проверка

Дата: 18 октября 2026 года. База diff: `31041ef9b2941efd91ca1382ac819e3884c48c71`.

## Реализовано

В диалоге посылки у доставки для клиента и расхода ателье отдельные селекторы
EUR/USD/UAH. При редактировании восстанавливаются исходные суммы и валюты.
Формы расходов сохраняют существующие селекторы; подсказка объясняет, что выбор
валюты задаёт единицу введённого числа и сам по себе число не конвертирует.
Сохранение асинхронное, без перезагрузки страницы.

Сумма доставки клиента применяется к заказу в валюте заказа по официальному
NBU/ECB курсу с целочисленным округлением. Исходная сумма и доказательство курса
сохраняются вместе. Неизменная доставка не переоценивается при обновлении статуса.
Расход перевозчика хранится один раз в связанной записи Expense в своей валюте.
Изменения расхода через финансы обновляют зеркало посылки и её версию; устаревшая
форма получает конфликт. Категория и комментарий существующего расхода сохраняются.
Платежи и инвойсы не переписываются. KeyCRM сохраняет согласованность валютных
данных при импорте и откате; все затронутые обычные writers продвигают версию посылки.

## Проверки

- Сервисные RED/GREEN: независимые валюты, рациональная конвертация и округление,
  сохранённый курс без переоценки, некорректные/устаревшие курсы, права, аудит,
  связанные расходы, конфликт версий, KeyCRM и старые NULL-строки.
- Изолированный PGlite применяет SQL к синтетической исторической таблице:
  старые суммы неизменны, новые поля NULL, некорректные комбинации отклоняются.
- Playwright: **9 PASS** с подменёнными API-ответами. Проверены запросы и
  восстановление исходных валют, отсутствие навигации при сохранении,
  desktop/mobile. Это не проверка установленного сервера или реальных курсов.
- Независимый визуальный review: **8 кадров**, 1366×950 и 390×950, без блокеров.
  Кадры покрывают посылку и общий диалог расходов; отдельный редактор расходов
  заказа и незакрытая модальным окном карточка проверены по коду/семантике,
  без заявления о полной пиксельной проверке этих двух поверхностей.

Полный `pnpm quality:check` с pnpm11.16.0 завершился с кодом0: **1659 PASS**
(1145 API + 488 web + 26 database), все typecheck, Nest и Next build PASS.
После восстановления генерируемого next-env.d.ts повторный web typecheck PASS;
`git diff --check` PASS. Compatibility, business/security, regression, visual и
дополнительные Standards/Spec review завершены без блокеров. Итоговый release gate: **PASS — LOCAL ONLY**, без блокеров.
Приватные логи, RED/GREEN, отчёты reviewers и скриншоты находятся в
`.local/shipment-expense-currency/`; скриншоты — `green-frozen/screens/`.

## Граница установки

Миграция `20261018120000_shipment_customer_charge_currency` подготовлена,
но **не применялась к рабочей или проектной базе**. Только три nullable-колонки
и CHECK, без backfill/удаления истории. Prisma generate создаёт клиент локально.
Новая схема нужна перед установкой API. После валютных записей старый writer-код
не является безопасным откатом: план установки должен сохранять валютную семантику.
Коммит, push, деплой и изменения сервера в этой задаче не выполнялись.
