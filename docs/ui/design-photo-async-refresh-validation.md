# Фото дизайна, обновление заказа и подтверждение профилей

## Изменения интерфейса (локально)

В редакторе дизайна поле «Фото дизайна» получает значок изображения, явную подсказку выбора файла и перечень форматов JPG/PNG/WebP. Текущая фотография и новая выбранная фотография показаны отдельно. Выбор и отмена файла сами по себе не отправляют изменения; временный object URL освобождается при замене и закрытии.

После подтверждения изменения данные заказа и серверные счётчики обновляются фоновыми запросами. Раскрытый заказ, вкладка и раскрытые экземпляры остаются смонтированными. Полной навигации страницы нет. Ошибка чтения после успешного сохранения оставляет редактор с замороженным изменением; повтор подтверждения повторяет только чтение, а не загрузку фото или mutation. Строгий callback выделен только для редактора состава; назначение мерок, архивирование и прочие потребители сохраняют прежний контракт.

REST, схема БД, финансовые расчёты, права и хранение изображений не изменены. Новая версия интерфейса в рабочую систему в рамках этой доработки не развёрнута.

READ ONLY сверка рабочей CRM обнаружила 319 canonical nonarchived nonspam LEAD с любым заказом: 316 с неархивным заказом, три только с архивными. Подтверждение личности клиента не зависит от оплаты или отмены заказа; финансовые cohorts не меняются.

Политика операции: только LEAD → ACTIVE и технический updatedAt, без создания/слияния карточек, изменения контактов, источников, менеджера, spam-флагов, заказов, оплат или мерок.
