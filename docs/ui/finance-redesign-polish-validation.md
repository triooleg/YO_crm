# Повторная сверка «Финансов» с утверждённым макетом

Дата: 15.10.2026. База: `e180e24`, deployed runtime `4707c4c` (0.1.58). Доработки находятся локально в Finance worktree; новая версия не развёрнута и не закоммичена.

## Что найдено и исправлено

- Сверка проведена при одинаковом размере1536×1024. KPI смещались вниз на15px, начало вкладок — примерно на41px. Исправлены отступы; KPI теперь начинаются наy138, как на макете, рабочая зона возвращена к его геометрии.
- У диаграммы расходов отсутствовал контрол месяца. Теперь оба MonthPicker меняют общий период отчёта, сохраняя валюту и остальные фильтры.
- Текст основных таблиц11px и правой панели10px увеличен до12px; восстановлены иерархия, яркий фиолетовый и градиенты, оформление кнопок/вкладок/пагинации. Настройки контролов находятся в отдельном варианте центральной Mantine theme; глобальная тема CRM не менялась. Вложенный provider явно сохраняет light даже при сохранённом dark/auto.
- Системные поля дат заменены Mantine DateInput с календарём слева и русским вводом. Обнаруженная американская трактовка01.03.2026 закрыта строгим parser: это1марта. Невозможные даты отклоняются; в API по-прежнему передаётся ISO YYYY-MM-DD.
- Устранено сжатие SVG: viewBox185px соответствует его высоте185px; область построения начинается околоx92/y346 противx92/y342 в эталоне. Ось получает округлённые деления без изменения денежных данных; подписи локализованы.
- Заголовок «Посл. оплата» помещается в колонку и сохраняет полный accessible label. Даты и способы оплаты не раздувают строки; длинный текст доступен через Tooltip. Пагинация справа, прямоугольное выделение текущей страницы.

Количество записей, реальные суммы, одна категория100% и отсутствие инвойсов не подменяются демонстрационными данными PNG. Лимиты серверной пагинации10/25/50/100 сохранены; пять демонстрационных строк не являются ограничением данных.

## Уточнение: доход только по фактическим оплатам

Подтверждён существующий источник `current.receivedMinor` и `monthlyTrend.receivedMinor`: действующие Payment records, исходные `amountMinor/currency`, дата `receivedAt` в отчётном месяце. Voided исключены. Стоимость заказов, инвойсы, долги и прогноз в доход не входят. Финансовый результат = полученные оплаты − учтённые расходы.

Добавлен regression-тест EUR/USD/UAH: большие неоплаченные заказы/инвойсы/прогноз не создают доход; учитывается только частичная реальная оплата; applied amount не добавляется вторично; void и соседние месяцы исключены. Ошибочная формула воспроизведена только в памяти теста, текущая модель прошла проверку. Денежный backend runtime не менялся.
