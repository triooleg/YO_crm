# Mantine Phase 6: раздел «Клиенты»

## Граница этапа

Этап переводит на общие Mantine-контролы только основные операторские сценарии
раздела «Клиенты»: поиск, создание клиента, добавление спортсмена и ручное
объединение карточек. Оболочка CRM, «Входящие», заказы, замеры, авторизация и
серверная бизнес-логика не менялись.

## Совместимость

- Общие `CrmButton`, `CrmActionIcon`, `CrmTextInput` и `CrmNativeSelect`
  сохраняют нативные `button`, `input` и `select`, имена полей и работу
  `FormData`. Все четыре оболочки явно передают DOM-ref через `forwardRef`.
- Создание клиента по-прежнему отправляет введённые поля в `POST /clients`.
- Добавление спортсмена сохраняет нормализацию имени и фамилии, не отправляет
  пустую дисциплину и использует прежний `POST /clients/:id/athletes`.
- Объединение карточек по-прежнему отправляет только `sourceClientId` в
  `POST /clients/:id/merge`; причины совпадения и ошибки берутся из русского
  словаря.
- Диалоги удерживают фокус, закрываются по `Escape` и возвращают фокус на
  открывшую кнопку. Кнопки отправки имеют явный `type="submit"`.

## Адаптивность

На мобильном экране подписи Mantine-кнопок не скрываются старым правилом для
подзаголовка. Действия страницы занимают полную ширину, а быстрые действия
карточки клиента переходят под имя. Для сворачивания списка добавлена
доступная русская подпись.

## Проверка

Failing-first unit-контракты закрепляют Mantine-компоненты, неизменные поля и
payload, а также клавиатурный фокус. Playwright выполняет создание клиента,
добавление спортсмена и объединение карточек с точным сравнением трёх POST
payload на 1920×1080, 1366×768 и 390×844; дополнительно проверяются поиск,
`Escape`, возврат фокуса, отсутствие horizontal overflow и ошибок страницы.
Скриншоты страницы и всех трёх диалогов просмотрены вручную во всех размерах.
Полный `pnpm quality:check` прошёл: database 9/9, API 468/468, web 272/272,
все typecheck и production builds. Полный браузерный набор — 46/46 PASS.
