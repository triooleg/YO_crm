# Официальные источники курсов EUR/USD/UAH

Дата проверки: 2026-10-11. Рассмотрены только первичные источники ECB и НБУ.

## Краткий вывод

- Для `EUR/USD` использовать ECB Data API: ряд `EXR/D.USD.EUR.SP00.A`, где значение означает количество USD за 1 EUR.
- Для `EUR/UAH` и `USD/UAH` использовать официальный API НБУ отдельными запросами по `EUR` и `USD`: для этих валют `rate` означает количество UAH за 1 EUR или 1 USD.
- Не смешивать источники при вычислении одного курса без явной политики происхождения. Расчёт `EUR/UAH ÷ USD/UAH` даст кросс-курс НБУ, который может отличаться от ECB из-за времени и методики фиксации.
- Оба сервиса доступны по HTTPS без API-ключа, но ни один из рассмотренных официальных документов не обещает SLA. Серверу нужны таймаут, ограниченные повторы с backoff, дневной кэш, сохранение даты курса и контролируемое поведение при устаревших/недоступных данных.

## ECB Data API — EUR/USD

**Endpoint**

```text
GET https://data-api.ecb.europa.eu/service/data/EXR/D.USD.EUR.SP00.A
```

Практичный запрос последнего наблюдения в CSV:

```text
GET https://data-api.ecb.europa.eu/service/data/EXR/D.USD.EUR.SP00.A?format=csvdata&lastNObservations=1
```

Для исторической даты/диапазона используются `startPeriod=YYYY-MM-DD` и `endPeriod=YYYY-MM-DD`. Официальная [документация data query](https://data.ecb.europa.eu/help/api/data) определяет схему URL, ключ `D.USD.EUR.SP00.A`, параметры дат и требует только HTTPS; [примеры запросов](https://data.ecb.europa.eu/help/api/data-examples) показывают тот же ряд и ограничение диапазона.

**Формат**

- `format=csvdata` — CSV; основные поля: `TIME_PERIOD`, `OBS_VALUE`, `OBS_STATUS`, а также измерения ряда.
- `format=jsondata` — SDMX-JSON (`application/vnd.sdmx.data+json;version=1.0.0-wd`), где наблюдения индексируются через метаданные `structure`.
- По умолчанию возвращается SDMX-ML 2.1 Generic Data. Поддержанные MIME-типы перечислены в [официальной документации content negotiation](https://data.ecb.europa.eu/help/api/content-negotiation). Для простого серверного адаптера CSV менее хрупок, чем индексная структура SDMX-JSON.

Проверенный пример ответа: [CSV за 2025-09-01](https://data-api.ecb.europa.eu/service/data/EXR/D.USD.EUR.SP00.A?format=csvdata&startPeriod=2025-09-01&endPeriod=2025-09-01) содержит `TIME_PERIOD=2025-09-01`, `OBS_VALUE=1.1715`.

**База и семантика**

Ключ читается как ежедневный (`D`) spot reference rate (`SP00`) USD относительно EUR; `CURRENCY=USD`, `CURRENCY_DENOM=EUR`. Значение `1.1715` означает **1 EUR = 1.1715 USD**. ECB исторически публикует котировку методом «1 euro = x foreign currency units»; это прямо зафиксировано в [решении ECB о стандарте котировки](https://www.ecb.europa.eu/press/pr/date/1998/html/pr980708_2.en.html).

**Дата публикации и оговорки**

- `TIME_PERIOD` — дата наблюдения, не timestamp публикации. Отдельного времени публикации в строке наблюдения нет.
- ECB обычно обновляет курсы около 16:00 CET в рабочие дни, кроме дней закрытия TARGET; процедура определения обычно проходит около 14:15 CET ([методология ECB Data Portal](https://data.ecb.europa.eu/methodology/exchange-rates)).
- Это справочный средний курс, публикуемый для информационных целей; ECB настоятельно не рекомендует применять его как цену сделки ([страница ECB о курсах](https://www.ecb.europa.eu/stats/exchange_rates/html/index.en.html)).
- Выходные и TARGET closing days не дают нового дневного наблюдения. Нельзя считать отсутствие сегодняшней строки нулём или ошибочным курсом: нужно хранить дату последнего принятого наблюдения и применять явный предел свежести.
- Официальная [таблица HTTP-статусов](https://data.ecb.europa.eu/help/api/status-codes) документирует `200`, `304`, `400`, `404`, `406`, `500`, `501`, `503`; опубликованного SLA или числового rate limit в рассмотренной документации нет. Для условного обновления поддерживается `If-Modified-Since`, а для дельт — `updatedAfter`.
- Проверка ряда `EXR/D.UAH.EUR.SP00.A` на дату исследования вернула `404`, поэтому ECB не следует считать источником UAH без отдельной повторной проверки доступности ряда.

**Пригодность для production**

Пригоден как официальный ежедневный справочный источник `EUR/USD`, если приложение фиксирует источник и дату, проверяет `OBS_STATUS`, не выдаёт курс за торговый/платёжный, кэширует результат и переживает временную недоступность. TLS используется и проверяется штатно; отключать проверку сертификата нельзя, даже если отдельный пример ECB с `curl` показывает `-k`.

## Официальный API НБУ — EUR/UAH и USD/UAH

**Endpoint**

```text
GET https://bank.gov.ua/NBUStatService/v1/statdirectory/exchangeNew?json&valcode=EUR&date=YYYYMMDD
GET https://bank.gov.ua/NBUStatService/v1/statdirectory/exchangeNew?json&valcode=USD&date=YYYYMMDD
```

Если параметры отсутствуют, API возвращает данные на текущую дату. `date` имеет формат `YYYYMMDD`, `valcode` нечувствителен к регистру. Это описано в официальной [инструкции НБУ по API курсов (PDF)](https://bank.gov.ua/admin_uploads/article/Instr_API_KURS_VAL_Full_eng.pdf).

**Формат**

- С флагом `json` возвращается JSON-массив. Поля: `r030` (числовой код), `txt` (название), `rate`, `cc` (буквенный код), `exchangedate` (`DD.MM.YYYY`) и `special`.
- Без `json` официальный endpoint возвращает XML.
- Проверенные ответы за 2025-09-01: [EUR](https://bank.gov.ua/NBUStatService/v1/statdirectory/exchangeNew?json&valcode=EUR&date=20250901) — `rate=48.196`, [USD](https://bank.gov.ua/NBUStatService/v1/statdirectory/exchangeNew?json&valcode=USD&date=20250901) — `rate=41.3203`.

**База и семантика**

НБУ публикует официальный курс гривны к иностранной валюте. Для EUR и USD количество единиц валюты равно 1, поэтому:

```text
EUR/UAH: 1 EUR = rate UAH
USD/UAH: 1 USD = rate UAH
```

Для общего адаптера нельзя предполагать, что у любой валюты номинал равен 1: официальная [таблица курсов НБУ](https://bank.gov.ua/ua/markets/exchangerates) содержит отдельную колонку «Кількість одиниць валюти / СПЗ» и для некоторых валют использует 10, 100 или 1000 единиц.

**Дата публикации и оговорки**

- `exchangedate` — дата официального курса, а не timestamp получения или публикации.
- Информация публикуется на сайте НБУ не позднее 15:30 в день установления/расчёта ([действующее положение НБУ, английский PDF](https://bank.gov.ua/admin_uploads/law/Regulation_10122019_148_24032025_eng.pdf?v=13), раздел III, пункт 13).
- На [официальной странице валютного рынка](https://bank.gov.ua/ua/markets/currency-market) НБУ раздельно показывает «дата розрахунку» и «починає діяти з». Поэтому сервер должен хранить эффективную дату курса и не подменять её временем загрузки.
- На выходные/праздники применяется установленный ранее курс согласно правилам НБУ; отсутствие нового расчёта не означает отсутствие действующего курса.
- Курс предназначен для бухгалтерского учёта, операций НБУ с ДКСУ и иных предусмотренных законом случаев. НБУ не обязуется покупать или продавать валюту по опубликованному курсу ([официальная таблица курсов](https://bank.gov.ua/ua/markets/exchangerates)). Это не коммерческий курс банка или платёжного провайдера.
- В официальной API-инструкции не указаны SLA, числовой rate limit, гарантия неизменности JSON-схемы или отдельный endpoint статуса. Пустой массив, неверная дата, неожиданный код валюты, сетевой сбой и просроченный курс должны обрабатываться явно.

**Пригодность для production**

Пригоден как первичный официальный источник UAH-курсов. Endpoint и документация доступны по HTTPS, запрос не требует API-ключа. Для production нужны проверка TLS, allowlist `EUR`/`USD`, строгая валидация единственной записи и `cc`, проверка конечного положительного `rate`, разбор `exchangedate`, дневной кэш с provenance и запрет молчаливой замены отсутствующего курса нулём или произвольным live-market значением.

## Рекомендуемый серверный контракт

Хранить для каждого принятого значения минимум:

```text
baseCurrency, quoteCurrency, rate, effectiveDate,
source (ECB | NBU), fetchedAt, sourceSeriesOrValcode
```

Денежные суммы CRM остаются integer minor units. Сам курс следует хранить как decimal/строку с фиксированной точностью, а конвертацию выполнять decimal-арифметикой с явно заданным округлением; IEEE-754 `float` для финансового расчёта не использовать.
