# Architecture decision records

This directory records durable, hard-to-reverse decisions. Create an ADR for a
cross-module architecture choice, new service, data-model or API contract
change, communication architecture, auth/RBAC, production workflow, or AI
architecture. Routine fixes, styling and local implementation choices do not
need ADRs.

Use the next four-digit number and a short kebab-case title, for example
`0001-example-decision.md`. Each record contains:

1. Title and status (`Proposed`, `Accepted`, `Superseded`).
2. Context and constraints.
3. Decision.
4. Consequences and rollback/migration implications.
5. Links to superseded or related decisions.

ADRs document decisions when they are made. Do not reconstruct a large
historical catalogue from assumptions.
