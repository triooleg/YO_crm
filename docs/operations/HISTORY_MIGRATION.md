# Контролируемый перенос истории переписки

Перенос использует существующие модуль истории и систему резервного копирования.
Браузерный сбор выполняется только локальным Windows-агентом в отдельном видимом
профиле. Пароль источника вводит администратор в браузере. Сервер не запускает
Playwright и не отправляет исторические сообщения клиенту.

Владельцу доступен раздел «Настройки → Перенос истории переписки». Сначала создайте
задание для бизнес-аккаунта и канала и сопрягите локальный агент. Секрет сопряжения
позволяет только передать пакеты в это задание; он не разрешает чтение CRM или
применение сообщений. Исходные диалоги сохраняют раздельные идентификаторы.

Для каждого диалога подтвердите существующего клиента. Сопоставление по одному
имени не является доказательством идентичности. Если контакт канала и клиент
заказа являются разными карточками, проверьте связи и используйте существующее
объединение клиентов. Перенос сообщений не выполняет такое объединение скрыто.

Нажмите «Проверить перед импортом». Сервер вычисляет группировку, проверяет порядок
истории, существующие сообщения, конфликтующие связи и записи на проверке.
Совпадение недоступных вложений не доказывает дубликат. Полнота источника указана
отдельно; успешный пилот не означает полный архив всех каналов.

«Подготовить импорт» требует текущий пароль владельца и сохраняет точный контекст
плана. Затем администратор запускает управляемый host issuer: он ставит конкретные
DATA и isolated-drill задания существующему backup-agent, проверяет физические
контрольные суммы и успешную очистку тестового восстановления. Только после этого
публикуется ограниченное по времени разрешение в host-owned каталоге. API видит
этот каталог только для чтения. Из браузера нельзя передать произвольный grant,
путь, базу данных, отчёт восстановления или список доверенных aliases.

Обновите статус. «Применить импорт» требует нового ввода текущего пароля и
подтверждения одного выбранного клиента по актуальным счётчикам. Изменение исходных
данных, сопоставлений, установленной сборки или состава базы требует новой проверки.
Существующие сообщения сохраняются; новые получают исходные даты. Повтор того же
импорта не создаёт дубликаты. Неоднозначные запоздавшие события канала сохраняются
для сверки вместо догадок или молчаливого удаления.

После применения исходные пакеты и сопоставления задания фиксируются. Сопряжение
можно отозвать. Пока импорт активен, закрытие задания недоступно: доступ к его
проверке и откату сохраняется.

После применения проверьте «Входящие» и историю выбранного клиента. Выборочный
откат требует отдельного подтверждения и скрывает только сообщения этого импорта,
сохраняя происхождение, audit, действующие сообщения и последующие поступления.
Он не разделяет объединённых клиентов и не восстанавливает рабочую базу из копии.

После первого операционного импорта, включая его выборочный откат, API обязан
содержать совместимую защиту исторической переписки. Хранение пяти старых версий
не означает, что любая из них пригодна для отката. Управляемые deployment/rollback
проверяют точные image IDs и встроенную capability под общей блокировкой с импортом.
Ручной обход этих проверок через Portainer/Docker не поддерживается. Восстановление
старой рабочей базы — отдельная аварийная операция с отдельным разрешением.

Финансовые расчёты, платежи и стоимость заказов перенос истории не изменяет.
Массовая запись и запуск следующих источников автоматически не выполняются.
