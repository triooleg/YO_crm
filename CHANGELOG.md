# Журнал версий Yoleotard CRM

Каждая production-сборка получает версию `X.Y.Z`, Git-тег `crm-vX.Y.Z` и
одноимённый GitHub Release. Тег указывает на точный commit, а описание ниже
фиксирует изменения и совместимость данных.

## [Unreleased]

- Изменения следующей сборки добавляются сюда до назначения версии.

## [0.1.9] - 2026-09-08

### Добавлено

- Во вкладке «Клиенты» CRM показывает вероятные совпадения по имени, телефону,
  e-mail, WhatsApp, Instagram и Facebook. Решение об объединении всегда
  подтверждает оператор; автоматического слияния нет.
- Во «Входящих» появился бейдж «Сводка» для клиентов с завершённой AI-сводкой,
  а в шапке переписки отображаются все связанные каналы клиента.

### Изменено

- При ручном объединении выбранная карточка остаётся основной. В неё
  транзакционно переносятся диалоги разных каналов, заказы, спортсмены, задачи,
  сообщения и связанная деловая история; дубль архивируется, а операция
  фиксируется в Activity и AuditLog.
- Старые контакты архивного дубля сохраняют постоянное перенаправление на
  основную карточку, поэтому новый входящий по прежнему номеру, e-mail или
  социальной идентичности не создаёт и не активирует дубль повторно.
- Клиентские AI-ограничения переносятся вместе с карточкой. Одинаковые runtime-
  настройки дедуплицируются, разные значения блокируют объединение до ручного
  решения, а режим `OFF` сохраняет приоритет как наиболее безопасный.
- Если в обеих карточках уже существует один и тот же канал, объединение
  блокируется до ручного разрешения конфликта, чтобы не потерять переписку.
- История в развороте заказа сначала показывает последние пять событий;
  остальные записи раскрываются по запросу оператора.

### Совместимость и откат

- Добавлены расширяющая таблица `ClientMergeRedirect`, две защитные функции и
  тринадцать write-path триггеров. Они сериализуют записи, напрямую связанные
  с клиентом, направляют поздние операции в основную карточку и запрещают
  изменение архивного источника; существующая деловая история не удаляется.
- До первого объединения откат приложения — `crm-v0.1.8`. После выполненного
  объединения безопасный полный откат требует pre-deploy backup; старая версия
  не умеет учитывать перенаправления при новых входящих сообщениях.

## [0.1.8] - 2026-09-06

### Исправлено

- Ручное формирование сводки больше не зависит от режима автоматических
  AI-ответов конкретного диалога. Оно использует настроенный OpenAI-контур
  обработки текста так же, как ручной перевод сообщений.
- Общие лимиты входного контекста, результата, частоты и параллельных запросов
  сохранены. Формирование сводки не включает автоматический анализ или отправку
  ответов клиенту.
- Общий слот длительной AI-операции удерживается до 10 минут без изменения
  исходного времени записи аудита.

### Совместимость и откат

- Миграций базы данных и изменений каналов связи нет. Существующие сводки,
  переписка и настройки сохраняются. Откат приложения — `crm-v0.1.7`.

## [0.1.7] - 2026-09-06

### Добавлено

- В правой панели «Входящих», сразу после вкладки «Файлы», добавлена вкладка
  «Сводка» с короткой русской выжимкой переписки для оператора.
- Оператор выбирает в календаре дату начала и вручную запускает генерацию.
  Даты уже сформированных сводок подсвечиваются зелёным; выбор такой даты
  открывает сохранённую актуальную версию.
- Сводка содержит пожелания клиента, договорённости, сроки, оплату, доставку,
  размеры, нерешённые вопросы и следующее действие. Для ответа используется
  переписка активного клиента в выбранном канале и рабочий контекст CRM.

### Изменено

- Версия CRM перенесена под название Yoleotard CRM в верхней панели и остаётся
  кнопкой открытия русского журнала сборок.
- Сводки получают отпечаток исходных сообщений. После изменения или удаления
  переписки старая сводка считается устаревшей и требует обновления.
- Длинная история обрабатывается пакетами до восьми AI-вызовов с сохранением
  каждого успешного шага; формирование можно безопасно продолжить с того же места.

### Совместимость и откат

- Миграция только добавляет служебные поля (nullable, кроме `updatedAt` с
  безопасным значением по умолчанию) и уникальный индекс в
  `ConversationSummary`; существующие сообщения, клиенты, заказы, файлы и
  прежние сводки не изменяются и не удаляются.
- Откат приложения доступен по `crm-v0.1.6`. Добавленные поля базы можно
  безопасно оставить для последующего возврата на новую версию.

## [0.1.6] - 2026-09-05

### Изменено

- Отдельная полноэкранная карточка заказа исключена из рабочих сценариев:
  заказ открывается и закрывается в едином развороте строки таблицы.
- В разворот перенесены статусы продажи, производства, оплаты и доставки,
  все позиции заказа и полный набор из 17 мерок для каждой позиции.
- Номер заказа и меню быстрых действий открывают тот же разворот. Статусы
  продажи и производства изменяются непосредственно в нём.
- Дублирующий крупный логотип удалён из левого меню. Фирменный знак остаётся
  в общей верхней панели и исходящих сообщениях согласно настройкам.
- Боковое меню убрано; обзор, входящие, заказы, клиенты, производство, финансы,
  доставка, задачи и настройки доступны из единой верхней навигации.
- Технический Facebook SID больше не отображается как e-mail в клиентах и
  развороте заказа.

### Добавлено

- В развороте доступны история платежей с реквизитами, счета с просмотром и
  скачиванием, требуемая предоплата, сведения о доставке, контакты клиента,
  пожелания и история действий.
- Изменение статуса сериализовано до ответа API и обновляет канонический заказ с
  новой записью истории; старый раздел заказов из карточки клиента больше недоступен.

### Совместимость и откат

- Миграций базы данных и изменений маршрутов API нет. В существующем поле
  `email` технический Facebook SID теперь возвращается как `null`; настоящий
  e-mail и остальные данные ответа сохраняются. Платежи, счета, мерки,
  сообщения, файлы и история не удаляются.
- Откат приложения доступен по `crm-v0.1.5`.

## [0.1.5] - 2026-09-05

### Исправлено

- Загруженный логотип сохраняет исходные пропорции и целиком помещается в
  шапке CRM, боковом меню, превью настроек и возле исходящих сообщений.
- Контейнер логотипа в боковом меню получил фиксированный размер и больше не
  растягивается по ширине панели.

### Добавлено

- В поле ответа можно вставить обычный текст или скопированное изображение:
  текст вставляется в позицию курсора, а изображение проходит существующую
  проверку типа и размера и добавляется как вложение.
- Для исходящих сообщений добавлено безопасное удаление из интерфейса CRM.
  Черновики, ошибочные и зависшие локальные отправки можно убрать, не теряя
  запись аудита; отправленные сообщения Chatwoot можно удалить через API
  подключённого Chatwoot с подтверждением результата до скрытия в CRM.

### Совместимость и откат

- Миграций базы данных нет. Удалённые из интерфейса сообщения сохраняются в
  базе и помечаются служебными метаданными; история аудита и активности не
  удаляется. Вставка из буфера использует действующие ограничения вложений.
- Удаление у получателя доступно только для Chatwoot, где CRM может вызвать
  документированный API удаления. В остальных каналах доступно скрытие из CRM.
- Откат приложения доступен по `crm-v0.1.4` без удаления данных или логотипа.

## [0.1.4] - 2026-09-05

### Добавлено

- В настройках интерфейса владелец или администратор может загрузить логотип JPG,
  PNG или WebP и независимо включить его в шапке CRM и возле исходящих сообщений.
- Вид спорта заказа изменяется прямо в таблице и сохраняется отдельной аудируемой
  операцией API.

### Изменено

- Верхняя панель и развёрнутое боковое меню из «Входящих» стали общей оболочкой
  всех разделов CRM. Поиск и значок непрочитанных ведут в единое окно сообщений.
- Клик по сроку заказа открывает календарь; столбец «Проблемы» удалён из таблицы
  и настроек столбцов.
- После успешного исходящего сообщения клиент сразу перемещается в начало списка;
  входящие и внешние исходящие продолжают сортироваться по серверному времени.

### Совместимость и откат

- Миграций базы данных нет: настройки логотипа используют существующую таблицу
  AppSetting, а файл хранится в постоянном томе uploads. История заказов и сообщений
  сохраняется.
- Откат приложения доступен по `crm-v0.1.3`; загруженный логотип можно повторно
  использовать после возврата на новую версию.

## [0.1.3] - 2026-09-05

### Изменено

- «Входящие» приведены к согласованному референсу: верхняя навигация, боковое меню
  с подписями, заголовок внутри списка и три независимые рабочие панели.
- Значки каналов и реальные счётчики сохранены. Фильтры покупок и активных заказов
  доступны в компактном меню, поиск в верхней панели синхронизирован со списком.
- Обновлены сообщения с аватарами, галереи, карточки клиента/задач/заказов/мерок,
  поля страны и местного времени. Ростовой стандарт не выдаётся за измеренный рост.
- Панель ответа: Ответ AI, перевод, шаблоны, выбор существующего шаблона запроса
  мерок, меню улучшения и сохранения текста как шаблона. Отправка и Ctrl+Enter сохранены.
- Исправлена адаптивная геометрия, закрытие мобильной карточки, поведение после
  сворачивания правой панели и рост редактора при многострочном тексте.

### Совместимость и откат

- API, интеграции, база данных и бизнес-правила не изменены; миграций нет.
- Откат приложения доступен по `crm-v0.1.2` без удаления переписки и файлов.
- Навигация показывает существующие разделы CRM. Кнопки видеосвязи и несуществующих
  модулей из референса не добавлены; реальные данные не заменяются макетом.

## [0.1.2] - 2026-09-05

### Добавлено

- Комментарии клиентов к публикациям Facebook, а также комментарии и live-комментарии
  Instagram поступают во «Входящие» как сообщения соответствующего клиента.
- Упоминания, ответы на истории и отправленные клиентом публикации Instagram получают
  в ленте отдельный контекст исходного материала с превью и ссылкой, когда Meta
  предоставляет эти данные.
- Реакции Facebook на публикации и комментарии отображаются в диалоге с указанием
  реакции и объекта, к которому она относится.
- На комментарий можно ответить прямо из CRM: ответ публикуется в той же ветке
  Facebook или Instagram. Для реакции, упоминания или истории используется личный
  ответ через существующий канал сообщений, если Meta разрешает переписку.

### Исправлено

- Технический Facebook SID вида `123…@facebook.com`, который Chatwoot может
  передавать как служебный идентификатор контакта, больше не сохраняется и не
  показывается как e-mail клиента. Ранее записанные значения скрываются, а
  настоящий e-mail можно импортировать вместо них при обновлении профиля.
- Подключение Facebook теперь проверяет обязательную webhook-подписку `feed`.
- OAuth Facebook запрашивает `pages_read_user_content` для получения пользовательских
  комментариев и `pages_manage_engagement` для публикации ответов.
- Подключение Instagram подписывает и проверяет поля `comments` и `live_comments`
  вместе с существующими сообщениями и реакциями, а OAuth запрашивает
  `instagram_business_manage_comments`.
- Технический идентификатор резервного Instagram-профиля больше не попадает в поле
  имени пользователя клиента.

### Совместимость и откат

- Миграций базы данных нет; существующие сообщения, реакции, файлы и каналы не
  изменяются.
- Для выдачи новых разрешений Facebook и Instagram потребуется повторное подключение
  соответствующего канала в настройках CRM.
- Откат к предыдущей сборке выполняется по тегу `crm-v0.1.1` без удаления данных.

## [0.1.1] - 2026-09-05

### Исправлено

- Ранее аватары клиентов Facebook импортировались, но после обновления CRM
  пропали: резервный Page Conversations путь сохранял только имя, а основной
  User Profile API в production возвращает `code 100/subcode 33`, пока функция
  Business Asset User Profile Access остаётся в режиме тестирования.
- CRM снова запрашивает аватар через оба допустимых Meta API и сохраняет его,
  когда Meta возвращает `picture`; отсутствие изображения больше не считается
  успешным восстановлением.
- Из Conversations API импортируется доступный e-mail точного участника диалога,
  без смешивания со страницей или другим клиентом.
- Массовое обновление разбито на пакеты до 10 профилей, чтобы запрос не обрывался
  по тайм-ауту reverse proxy.
- В отчёте массового обновления профилей отдельно учитываются аватары, полученные как
  через User Profile API, так и через Conversations API.
- Если конкретная версия Meta Graph API не поддерживает вложенное поле
  `picture`, CRM повторяет прежний безопасный запрос имени и не ломает уже
  работавший импорт профилей.

### Добавлено

- Внизу интерфейса постоянно отображается текущая версия CRM; в подсказке
  также доступен точный Git commit сборки.
- Docker-сборка получает `CRM_VERSION` и `CRM_COMMIT`.
- Публикация тега `crm-v*` автоматически создаёт GitHub Release с описанием
  этой версии из данного журнала.

### Совместимость и откат

- Миграций базы данных нет.
- Откат к этой сборке выполняется по тегу `crm-v0.1.1`; данные клиентов и
  история сообщений не удаляются.

## [0.1.0] - 2026-09-05

### Базовая сборка

- Зафиксировано последнее рабочее состояние CRM до введения обязательной
  версионности: обновлённые «Входящие», сквозные каналы, реакции, ответы,
  статусы прочтения, короткие видео и исправленная таблица заказов.
- Восстановлены прокрутка основного чата, компактные значки каналов со
  счётчиками и превью файлов в боковой панели.

### Совместимость и откат

- Это исходная точка отката перед `0.1.1`, соответствующая commit
  `e421f564b79b187edaff0cacc5fec94e7b1e8c16`.
- Сборка не содержит нового механизма отображения версии внутри интерфейса.
