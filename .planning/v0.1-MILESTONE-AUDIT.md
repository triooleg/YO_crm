`gaps_found`. The deployed application builds and its implemented happy paths work, but the current roadmap overstates completion of phases 0–6. Four integrity/operations gaps must be closed before those phases can be treated as verified complete.

## Critical gaps

### 1. Measurement ownership at order creation

The API validates that selected athletes belong to the order client, but it does not verify that each `measurementId` belongs to the selected athlete/client. Foreign keys only prove that a snapshot exists. A crafted request can attach another customer's immutable measurement snapshot to an order.

Required closure: validate top-level and item-level athlete/measurement/client relationships transactionally; add negative API tests for cross-client and cross-athlete IDs.

### 2. Configured 50% deposit is not connected to orders

Settings persist `orders.depositPercent`, yet the order form requires a manually entered absolute deposit and the order service stores it directly. The business rule “normal custom-order deposit is 50%” is therefore not defaulted or enforced by the production path.

Required closure: define when the configured percentage is a default versus mandatory rule; calculate minor units server-side and allow explicit audited override only for authorized roles.

### 3. Shipping invariants can be bypassed

ShipmentService correctly validates tracking, chronology and terminal transitions, but the generic order status endpoint can independently mutate `shippingStatus`. It can produce `SHIPPED` without a shipment/tracking number or reverse terminal states.

Required closure: remove shipping mutations from the generic status endpoint or delegate them to ShipmentService; add cross-route invariant tests.

### 4. Backup/restore flow is not executable

`docs/BACKUP_RESTORE.md` references `scripts/backup.sh` and `scripts/restore.sh`, but the directory and scripts do not exist.

Required closure: implement, test and document database plus upload-volume backup/restore, including a restore drill.

1. Measurement ownership validation — data-integrity/security risk.
2. Shipping invariant unification — state-integrity risk.
3. Deposit rule wiring — core commercial rule.
4. Backup/restore implementation and drill — operational risk.
5. Global auth/role UX and read-role policy.
6. Continue Phase 7 external channel integrations and templates.
